Trả lời lý thuyết

Câu 1: position absolute và relative

relative: phần tử vẫn nằm trong luồng, có thể dịch bằng top/left và trở thành mốc cho phần tử con absolute. absolute: phần tử rời khỏi luồng và định vị theo tổ tiên gần nhất có position khác static.

.card{position:relative}
.badge{position:absolute;top:8px;right:8px}

Responsive: dùng relative cho khung chứa và absolute cho huy hiệu nhỏ, kết hợp đơn vị %, rem, flexbox. Tránh dùng absolute với tọa độ px cố định cho cả bố cục vì dễ chồng lấn trên màn hình nhỏ. Hosting chỉ phục vụ file tĩnh, nên độ tương thích phụ thuộc vào trình duyệt và thiết bị: cần thẻ meta viewport và kiểm tra bằng chế độ thiết bị của DevTools trước khi deploy.

Câu 2: Domain, hosting, DNS

Quy trình: (1) đăng ký tên miền ở nhà cung cấp; (2) đưa code lên hosting tĩnh; (3) khai báo bản ghi DNS (A hoặc CNAME) trỏ tên miền về hosting; (4) bật HTTPS. DNS là hệ thống dịch tên miền thành địa chỉ IP để trình duyệt tìm đúng máy chủ.

Công cụ không cần server riêng: GitHub Pages (push code lên repo rồi bật Pages) và Netlify (kết nối GitHub, tự deploy mỗi lần commit).

Rủi ro nếu cấu hình sai: không bật HTTPS (dữ liệu bị nghe lén), để lộ khóa API trong mã JavaScript hoặc repo công khai, trỏ DNS sai khiến subdomain bị chiếm quyền, để tên miền hết hạn bị người khác mua.

Câu 3: var, let, const

var có phạm vi hàm, được hoisting và có giá trị undefined trước khi gán. let và const có phạm vi khối; chúng cũng được hoisting nhưng ở vùng chết tạm thời (TDZ), truy cập trước khai báo sẽ báo lỗi. const không gán lại được (nhưng nội dung đối tượng vẫn sửa được).

for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3
for (let j = 0; j < 3; j++) setTimeout(() => console.log(j)); // 0 1 2

Lỗi ở ví dụ đầu: cả ba hàm dùng chung một biến i. Cách debug: mở DevTools, vào Sources, đặt breakpoint trong vòng lặp, xem giá trị trong ô Scope/Watch và Console; sau đó đổi var thành let.

Câu 4: Event Delegation

Thay vì gắn sự kiện cho từng phần tử con, ta gắn một trình nghe ở phần tử cha và dựa vào cơ chế nổi bọt (bubbling) để biết phần tử nào được bấm qua event.target.

list.addEventListener('click', e => {
  const li = e.target.closest('li');
  if (li) li.classList.toggle('done');
});
list.append(document.createElement('li')); // mục thêm sau vẫn bấm được

Lợi ích: ít trình nghe hơn nên tiết kiệm bộ nhớ, phần tử thêm động vẫn hoạt động. Kết hợp CSS: chỉ đổi class (ví dụ .done) để trình duyệt áp style, giúp mã gọn và hiệu suất tốt hơn.
